# Original ES2 Score 介面呈現規格

> **[PROJECT-CANON]** 本文件是 ES2-KING `score` 指令介面的永久詳細規格。

## 1. 基準證據

主要視覺證據：專案擁有者提供的 Original ES2 實機 `score` 截圖。

證據等級：**[Player Memory / Archived Gameplay Visual Evidence]**。若日後取得 Original Mudlib Source Code（原始程式碼）中對應 `score` 指令，應以原始碼交叉驗證文字、欄位、顏色與數值邏輯；不得因程式重建方便而改變截圖所證明的版面風格。

目前對話中的原始截圖尚未直接保存進 GitHub Repository，因此本文件只記錄可以從截圖可靠確認的介面特徵；圖片檔本身日後應另存為未修改的歷史證據。

## 2. 已確認的整體呈現

- 黑色終端機背景。
- 純文字 MUD（Multi-User Dungeon／多人文字地下城）介面，不使用現代圖形化卡片。
- 使用 ANSI Color（終端機文字色彩控制）呈現不同資訊與狀態。
- 上方為人物身分／稱號／名稱與人物敘述區。
- 中上方為八項人物基本屬性，採多欄排列，而非單一直列表格。
- 中段存在人物狀態數值與長條式視覺表示。
- 精、氣、神使用不同色彩的文字／狀態條呈現。
- 下段另有能力、經驗或其他人物資料區域。
- 整體排版以 Original ES2 實機畫面為準，不重新設計成現代 RPG UI（User Interface／使用者介面）。

## 3. 八項基本屬性

目前 ES2-KING 已鎖定的程式欄位與中文對應如下；實際 `score` 排列位置仍應依 Original 截圖與原始碼逐步核對：

- `str`：臂力
- `cps`：膽識
- `int`：悟性
- `spi`：靈性
- `cor`：定力
- `dex`：機敏
- `con`：根骨
- `wis`：慧根

禁止因現代 RPG 習慣自行更名、重新分組或改變排列。

## 4. 精／氣／神狀態區

從實機截圖可以確認：

- 狀態數值不是單純的現代化 `30 / 30` 卡片列表。
- Original ES2 使用文字數值搭配重複字元形成的長條視覺表示。
- 不同狀態使用不同 ANSI 色彩。
- 條狀區的確切字元、顏色代碼、長度計算公式與滿／損狀態規則：**待考證**。
- 截圖中各列與 Gin／Kee／Sen 的精確一對一名稱與順序，如尚未由原始碼確認：**待考證，不自行猜測**。

## 5. 上方人物資訊區

截圖可確認存在人物稱號／名稱與描述性文字，並使用不同顏色強調部分資訊。

以下細節目前標記 **待考證**：

- 每個稱號欄位的正式名稱。
- 英文 ID／帳號／角色名稱的確切顯示規則。
- 年齡／出生日期文字的完整生成公式。
- 種族、職業、門派是否在此區固定顯示，以及確切位置。

不得依一般 MUD 經驗自行補齊。

## 6. 下方能力／經驗資訊區

截圖可確認下方另有多組人物數值與文字資訊，但因目前畫質不足，以下項目一律 **待考證**：

- 各欄位正式名稱。
- 數值單位。
- 是否為經驗、潛能、戰鬥經驗、評價、等級或其他 Original ES2 數值。
- 欄位排列順序與顏色規則。

後續優先從 Original `score` 指令原始碼、玩家物件資料結構、歷史文件與更清晰實機截圖交叉確認。

## 7. 禁止事項

後續任何 ES2-KING 開發者或 AI 不得：

1. 將 `score` 改成現代 RPG 卡片式介面。
2. 為了美觀自行加入方框 Dashboard（儀表板）。
3. 將八項屬性任意重新排序或改名。
4. 把截圖看不清楚的文字自行猜成常見 MUD 欄位。
5. 用 ES2-KING Expansion（擴充設定）反向覆寫 Original ES2 歷史介面。
6. 修改保存用途的 Original Score 截圖。

## 8. 更新規則

每取得一份新的 Score 證據：

1. 先保存原始證據。
2. 標記來源與證據等級。
3. 與本文件現有項目交叉比對。
4. 只更新被新證據確認的欄位。
5. 仍不確定的內容繼續保留「待考證」。
6. 若證據衝突，依 `AGENTS.md` 的 Original ES2 證據優先順序處理。

## 9. 開發完成條件

未來 `score` Runtime（實際執行環境）重建至少需要驗證：

- 黑底文字 MUD 呈現結構保持一致。
- 八項屬性均能從實際角色資料讀取。
- 精／氣／神使用 Original 風格的彩色文字狀態條。
- 人物資訊與下方數值區依已確認 Original 欄位排列。
- ANSI 顏色在 Telnet（文字連線協定）實際連線中正常顯示。
- Regression Test（回歸測試）防止後續修改把 Score 重新變成現代化 UI。

在上述欄位尚未完全考證前，允許分階段重建，但每個未確認內容都必須明確標記「待考證」。
